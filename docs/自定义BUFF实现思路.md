# 野蛮人大作战 · 自定义 BUFF 实现思路

记录这套工具从“找到卡池”到“稳定改写”的完整过程，方便后续维护或移植到同引擎的其他游戏。

游戏版本：4399 渠道 PC 版，`GameLogic.dll` / `libcocos2d.dll`，2026-11 实测。

---

## 1. 目标

升级时会刷出三张技能卡，玩家点一张获得对应 BUFF。目标是**在点击之前把三张卡改成指定技能**，从而绕过随机。

不改已拥有的技能槽位，也不改伤害/体力等服务端结算值。

---

## 2. 角色对象与卡池

### 2.1 指针链

```
libcocos2d.dll + 0xAAAEEC
  → +0xB4
  → +0x2B8
  → +0x2B4
  → +0x2E4        = 角色对象（Entity/Hero）
```

角色对象 `+0x3D4` 是 `CSkillRandom`（RTTI 可确认），其内部布局（实测）：

| 偏移 | 含义 |
|---|---|
| `+0x1C` | 当前三张卡的 `std::vector<SSkillPlanConfig>`：begin |
| `+0x20` | end |
| `+0x24` | capacity |
| `+0x3C` | 本局携带的主动技能配置 ID |
| `+0x4C` | PreOperation 列表（升级前预生成） |

### 2.2 卡条目结构

vector 每个元素 16 字节：

```
struct SSkillPlanConfig {
    SkillConfig* config;   // +0x00 指向技能配置对象
    int          weight;   // +0x04 权重（15/30/60/75 ...）
    void*        name1;    // +0x08 名称字符串
    void*        name2;    // +0x0C 第二名称/描述
};
```

技能配置对象：

```
+0x00  vtable
+0x04  cfgId   // 9 位配置 ID，例如 120160020 = 吸血lv1
...
```

只要拿到 `config` 指针，把它写进卡条目，游戏点击时就会按该配置创建技能。

### 2.3 条目数量

`count = (end - begin) / 16`，每升一级追加 3 条，初始 3 条。`count/3` 即当前等级。

---

## 3. 从技能 ID 到配置对象

游戏里同一技能有“技能 ID”（如 210131）与“配置 ID”（如 120160020）。卡池里存的是配置对象指针，所以需要一张映射表：

1. 从 `asset.vfs` 解出 `config.hero.entityrandomskillplans` 等表，得到 `技能ID → 配置ID → 名称`
2. 在进程堆里扫描该配置 ID（4 字节），并校验前 4 字节像代码指针（`0x00400000 ~ 0x7FFF0000`），得到配置对象地址
3. 缓存结果，后续直接按 CFG 取指针

工具里的 `work/buff_catalog.csv` 就是这样生成的（99 条去重后的技能）。

---

## 4. 改写流程

```
apply(slots):
  1. 刷新角色对象，取 vector 的 begin/end
  2. count < 3 → 还没出卡，拒绝
  3. 对每个非空 slot：
       skill = BY_ID[slot]
       若配置对象未缓存 → 扫描堆找到它
       生成 16 字节条目：{config, 原权重, 原名称指针...}
  4. 写入 vector 最后 3 条（begin + (count-3)*16）
  5. 启动装填线程：每 80ms 重写一次
     一旦 count 变化（点卡或升级）→ 停止
  6. 120 秒后自动过期
```

为什么每 80ms 重写：游戏在出卡后还会刷新卡面/预操作列表，偶尔覆盖我们写入的条目；持续重写能保证点击时一定是目标技能。点卡后 `count` 增加，线程自动退出，不会影响下一手。

---

## 5. 预设队列与逐级自动

- 每个方案 9 个槽位（对应 9 次升级），保存在 localStorage
- 前端监听 `/api/state` 的 `level` 变化：等级增加 = 新一手牌
- 新一手出现时，若开启自动，取当前方案第 `qIndex` 位技能，调用 `apply([id, id, id])`——三张卡都写成同一个技能，玩家随便点哪张都拿到目标
- 成功后 `qIndex++`，9 次用完停止

这样即使不修改已拥有槽位，也能保证整局拿到的 BUFF 全部符合预设。

---

## 6. 启动弹窗补丁

游戏启动时会弹一个报错框，挡住窗口。定位到 `GameLogic.dll + 0x4D02A`：

```
call dword ptr [MessageBoxA]   ; 6 字节
```

改写为：

```
add esp, 0x10
nop nop nop
```

即跳过调用并平衡栈。每次连接时检查并在位则跳过，失败会记录日志。

## 7. 检测边界（实测）

用两个账号组队开真人局，分别修改不同数据：

| 修改项 | 结果 | 结论 |
|---|---|---|
| 人物大小 | 不踢 | 纯表现字段，服务端不校验 |
| 攻击距离 | 被踢 | 参与命中判定，主机/服务端会核对 |
| 技能 ID（改卡池） | 被踢 | 上报的技能不在服务端候选列表 |
| 体力（无限） | 被踢 | 服务端自己也在扣体力，差值暴露 |

结论：真人局是**主机/服务端权威模拟**，只校验参与结算的字段；改这些字段无法“过检测”，因为对方有自己那份状态。

人机 / PVE 局由本地模拟，不受此限制。

## 8. 未完成 / 后续方向

- **直接改已拥有技能槽位**：试过修改疑似槽位数组（`0x26CDE0xx` 一带），确认改到的是方案缓存，界面无变化；需要进一步用硬件断点抓“添加技能”的写入函数
- **协议层**：抓过 `libtms!WSASend`、`sendto`、`websockets!send`、`libcocos2d!send`，只看到 4 字节心跳；战斗包可能在更底层或加密，未继续
- **图标**：官网只整理了 18 张，剩余技能显示首字徽章；完整图集在 `asset.vfs` 的 `gui/icon.png`（2048×2048，96px 网格），需要解析图集帧表
