# 野蛮人大作战 · 自定义 BUFF 编排台

一个本地桌面工具：读取游戏内升级时刷出的三张技能卡，按预设把它们替换成想要的技能，并支持 9 级升级的自动装填。

配套一份完整的内存结构分析与实现思路，见 [docs/自定义BUFF实现思路.md](docs/自定义BUFF实现思路.md)。

> 仅建议在人机 / PVE 对局使用。真人局存在服务端数值校验，修改结算相关数据会被踢回大厅（不封号）。

---

## 功能

| 功能 | 说明 |
|---|---|
| 三卡改写 | 写完卡池数组后，游戏内点击任意一张卡即发放目标技能 |
| 预设方案 | 多套 9 技能方案，切换、改名、删除，保存在浏览器 localStorage |
| 队列拖放 | 技能拖到队列格；队列格之间拖动交换位置；右键清空 |
| 逐级自动 | 每级自动装填当前队列位，三张卡都写成同一技能，随便点 |
| 装填保持 | 默认 120 秒内有效，超时未点卡则失效 |
| 弹窗补丁 | 每次连接自动打掉启动时的报错弹窗 |
| 自绘界面 | WebView2 + Vue3 + Tailwind，无边框窗口、自绘标题栏、高 DPI |

## 快速开始

便携版：

```
dist\野蛮人BUFF\WildsBuff.exe
```

先启动游戏，再启动工具；进入对局后左侧出现技能库与三张卡。

> `dist` 与 `web` 是构建产物，不随仓库提交；仓库只含源码。

## 构建

```bat
:: 前端
cd webapp
npm install
npm run build

:: 宿主（.NET 9 + WebView2）
dotnet build app\WildsBuff.csproj -c Release

:: 运行
python server.py
```

把 `app\bin\Release\net9.0-windows\*`、`web\`、`server.py`、`assets\app.ico`、`assets\logo.png`、`icons\` 放到同一个目录即可便携运行。

## 项目结构

```
├─ server.py            本地后端：进程读写、卡池改写、HTTP API
├─ app/                 C# WebView2 宿主（无边框窗口、自绘标题栏、内嵌图标）
├─ webapp/              Vue3 + Tailwind 前端源码
├─ assets/              LOGO 源文件与 ICO
├─ icons/               技能图标（从官网整理，按 CFG 命名）
├─ tools/               逆向辅助脚本（配置表提取、内存扫描、弹窗补丁等）
│  └─ research/         一次性研究脚本（指针扫描、协议抓包尝试）
├─ docs/                实现思路、内存偏移、调研报告
└─ work/                运行期临时文件（不提交）
```

## 工作原理（简版）

1. 通过 `libcocos2d+0xAAAEEC` 的多级指针找到角色对象
2. 角色 `+0x3D4` 是 `CSkillRandom`，`+0x1C` 是当前三张卡的 vector
3. 每个卡条目 16 字节：`{配置对象指针, 权重, 名称指针1, 名称指针2}`
4. 配置对象 `+4` 是 9 位配置 ID；据此建立技能目录
5. 把目标技能的配置指针写进卡条目，点击时游戏就按新技能发放
6. 装填线程每 80ms 重写一次，卡片 vector 变化（点卡/升级）后自动停止

完整分析（含偏移、结构图、检测边界）见 [docs/自定义BUFF实现思路.md](docs/自定义BUFF实现思路.md)。

## 已知限制

- **真人局会被踢**：服务端/主机对技能 ID 与结算数值做校验；实测人物大小不触发、攻击距离触发
- **不能直接改已拥有槽位**：尝试过方案缓存数组，确认无效；目前只能改“下一手卡池”
- **图标不全**：官网只整理了部分技能图，未覆盖的显示首字徽章
- **卡片文字不变**：改写后游戏内卡片文字仍是旧的，实际发放以工具为准

## 研究脚本
